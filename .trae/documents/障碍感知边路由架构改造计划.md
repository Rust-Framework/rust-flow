# 障碍感知边路由架构改造计划

## 摘要

当前连线算法存在两个架构性顽疾：

1. **主线断链**：`align_linear_chain`（linear.rs:93-96）在合并点（入度 ≥ 2）处断链，导致 Adapter（入度 2）之后的 Loop、Summarize、End 不与 Check 对齐到同一条中心线。
2. **零障碍感知**：ReactFlow 路径算法（`smoothstep_path`/`bezier_path`）是纯几何算法，仅基于 src/dst 坐标和端口方向计算路径，完全不知道画布上其他节点的存在，导致连线穿过节点。

本计划通过两个核心改造彻底解决：
- **Phase 1**：新增 `align_main_flow` 步骤，将非分支、非 body 的主流节点对齐到中位数横轴，跨越合并点不断链。
- **Phase 2-5**：引入 Grid A* 障碍感知路由器，在占用网格上搜索避障正交路径，渲染层优先使用路由 waypoints，命中测试同步适配。

## 当前状态分析

### 问题根因（已通过代码阅读确认）

**问题 4 — 主线不对齐**：
- `align_linear_chain`（[linear.rs](file:///d:/GitCode/RF/rust-agent-flow/crates/core/src/layout/dagre/linear.rs) L93-96）使用 Kahn 拓扑排序，仅在「前驱出度=1 且后继入度=1」的简单链中对齐。
- Check 节点出度 3（if_0/if_1/else），Adapter 入度 2（Search+ToolCall）→ 链在 Check→Adapter 处断裂。
- 断裂后 Adapter、Loop、Summarize、End 保留 dagre 原始位置，不在 Check 的中心线上。

**问题 2/3 — 边穿过节点**：
- `smoothstep_path`（[edge_path.rs](file:///d:/GitCode/RF/rust-agent-flow/crates/core/src/geometry/edge_path.rs) L427-436）调用 `rf_get_points`，仅基于 src/dst 坐标 + port side 计算正交拐点，零障碍感知。
- Check→Notify 边和 Search→Adapter 边的路径直接穿过中间节点区域。

## 实施方案

### Phase 1：主流对齐（core 层）

**新建文件**：`crates/core/src/layout/dagre/main_flow.rs`

**算法设计**：

1. **识别分支目标**：遍历所有边，收集 `source_port` 为 `if_N` 或 `else` 的目标节点 → `branch_targets: HashSet<NodeId>`
2. **识别循环体节点**：从 `loop_groups` 收集所有 body 节点 + loop 节点本身 → `excluded: HashSet<NodeId>`
3. **收集主流节点**：`graph.nodes()` 中不在 `branch_targets` 且不在 `excluded` 的节点
4. **计算中位数**：收集所有主流节点的 cross-axis 中心坐标（Horizontal=`pos.y + size.h/2`，Vertical=`pos.x + size.w/2`），排序取中位数
5. **对齐**：将所有主流节点的 cross-axis 坐标设为 `median - size_cross/2`

**关键函数签名**：

```rust
pub(super) fn align_main_flow(
    graph: &FlowGraph,
    positions: &mut std::collections::HashMap<crate::graph::NodeId, PointF>,
    direction: LayoutDirection,
    loop_groups: &std::collections::HashMap<crate::graph::NodeId, std::collections::HashSet<crate::graph::NodeId>>,
)
```

**管线集成**（`dagre/mod.rs`）：

在 `align_linear_chain` 之后、`reserve_loop_back_edge_space` 之前插入第 3 步：

```
1. reorder_branch_targets
2. align_linear_chain
3. align_main_flow          ← NEW
4. reserve_loop_back_edge_space
5. align_loop_in_sources
6. align_loop_done_target
7. align_loop_body_target
8. avoid_body_group_collision
9. align_post_done_chain
```

**为什么在这个位置**：
- 在 `align_linear_chain` 之后：简单链已对齐，中位数由已对齐的节点主导，拉齐断裂部分
- 在 `reserve_loop_back_edge_space` 之前：确保 Loop 及其后续节点在预留空间前已在主流线上，后续 loop 步骤做微调

**Demo 验证**：主流节点 = {Start, Vars, Agent, Planner, Check, Adapter, Summarize, End}（排除 ToolCall/Search/Notify=分支目标，Process=body，Loop=loop节点）。中位数由已对齐的 Start-Vars-Agent-Planner-Check 链主导，拉齐 Adapter/Summarize/End。

#### 2.1 OccupancyGrid（`grid.rs`）

```rust
pub struct OccupancyGrid {
    cells: Vec<bool>,   // true = 被占用（障碍）
    width: usize,
    height: usize,
    origin: PointF,     // cells[0][0] 对应的逻辑坐标

}

impl OccupancyGrid {
    /// 从所有节点边界的并集构建网格。
    /// bounds = 所有节点 bounds 的 union，外扩 margin。
    pub fn new(bounds: RectF, cell_size: f32) -> Self;

    /// 将矩形区域标记为障碍（自动裁剪到网格范围）。

    pub fn clear_obstacle(&mut self, rect: RectF);

    pub fn is_blocked(&self, x: usize, y: usize) -> bool;

    /// 逻辑坐标 → 网格坐标
    pub fn to_grid(&self, p: PointF) -> (usize, usize);

    /// 网格坐标 → 逻辑坐标（格子中心）
    pub fn to_logical(&self, x: usize, y: usize) -> PointF;
}
```

#### 2.2 A* 寻路（`astar.rs`）

```rust
/// 在占用网格上搜索从 start 到 goal 的最短正交路径。
///
/// - 4 方向移动（上下左右，不斜行）→ 正交路径
/// - 启发式：曼哈顿距离
/// - turn_penalty：每次方向变化增加额外代价，鼓励直线
/// - start_direction：约束第一步的移动方向（由 src_side 决定）
/// - goal_direction：约束最后一步的进入方向（由 dst_side 决定）
///
/// 返回网格坐标路径（含 start 和 goal），失败返回 None。
pub fn find_path(
    grid: &OccupancyGrid,
    start: (usize, usize),
    goal: (usize, usize),
    start_direction: Option<Direction>,
    goal_direction: Option<Direction>,
    turn_penalty: f32,
) -> Option<Vec<(usize, usize)>>;

#[derive(Clone, Copy, PartialEq, Eq)]
pub enum Direction { Up, Down, Left, Right }

impl Direction {
    pub fn from_side(side: PortSide) -> Self;
    pub fn delta(&self) -> (isize, isize);
}
```

**方向约束实现**：
- `start_direction`：A* 的起始邻居仅保留沿 `src_side` 外向方向的格子（如 Right→仅向右扩展第一步）
- `goal_direction`：仅接受从 `dst_side` 外向方向反方向进入 goal 的路径（如 Left→仅从右方进入 goal）
- 若 start 或 goal 被障碍包围，放宽约束为 None（允许任意方向）

#### 2.3 路径简化（`simplify.rs`）

```rust
/// 移除共线点，仅保留方向变化的拐点。
/// 输入：网格坐标路径（含端点）
/// 输出：简化后的网格坐标路径（含端点）
pub fn simplify_path(points: &[(usize, usize)]) -> Vec<(usize, usize)>>;
```

算法：遍历路径，若当前点与前一点、后一点共线（方向向量相同），则移除当前点。

#### 2.4 模块入口（`mod.rs`）

```rust

pub mod grid;
pub mod simplify;

use crate::geometry::{PointF, RectF};
use crate::graph::PortSide;

/// 路由单条边。
///
/// - `src`, `dst`：端口位置（逻辑坐标）
/// - `src_side`, `dst_side`：端口方向
/// - `obstacles`：障碍矩形列表（已外扩 margin）
/// - `grid_size`：网格单元大小（逻辑像素）
///
/// 返回 waypoints（逻辑坐标，含 src 和 dst），失败返回 None。
pub fn route_edge(
    src: PointF,
    dst: PointF,
    src_side: PortSide,
    dst_side: PortSide,
    obstacles: &[RectF],
    grid_size: f32,
) -> Option<Vec<PointF>> {
    if src.distance_to(dst) < 1.0 {
        return Some(vec![src, dst]);
    }
    // 1. 计算边界 = obstacles 的 union，外扩 grid_size
    // 2. 构建 OccupancyGrid
    // 3. 标记所有 obstacles
    // 4. to_grid(src) → start, to_grid(dst) → goal
    // 5. find_path(grid, start, goal, src_side→dir, dst_side→dir, turn_penalty)
    // 6. simplify_path
    // 7. 转换为逻辑坐标
}

/// 常量

pub const OBSTACLE_MARGIN: f32 = 15.0;
pub const TURN_PENALTY: f32 = 2.0;
```

### Phase 3：路由编排（gpui 层）

**新建文件**：`crates/gpui/src/editor/routing.rs`

**职责**：遍历所有非 LoopBack 边，调用 `route_edge` 计算避障路径，返回 `HashMap<EdgeId, Vec<PointF>>`。

```rust
use std::collections::{HashMap, HashSet};
use rust_agent_flow::{EdgeId, FlowGraph, NodeId, PointF, PortSide, RectF, route_edge};
use crate::node::NodeRegistry;
use super::flow_editor::LayoutDirection;
use super::rendering::compute_edge_endpoints;

/// 为所有非 LoopBack 边计算路由路径。
///
/// LoopBack 边（target_port == "loop_in"）跳过，使用专用 loop_back_path。
/// 路由失败的边不包含在返回值中，调用方回退到几何路径。
pub(crate) fn route_all_edges(
    graph: &FlowGraph,
    registry: &NodeRegistry,
    body_nodes: &HashSet<NodeId>,
    layout: LayoutDirection,
    src_side_default: PortSide,
    dst_side_default: PortSide,
) -> HashMap<EdgeId, Vec<PointF>> {
    // 1. 收集所有节点 bounds 作为障碍（外扩 OBSTACLE_MARGIN）
    let obstacles: Vec<RectF> = graph.nodes()
        .map(|n| n.bounds().expand(rust_agent_flow::routing::OBSTACLE_MARGIN))
        .collect();

    // 2. 遍历边，跳过 LoopBack
    let mut routes = HashMap::new();
    for edge in graph.edges() {
        if edge.target_port.as_deref() == Some("loop_in") {
            continue;
        }
        let (src, src_side, dst, dst_side) = compute_edge_endpoints(
            edge, graph, registry, layout,
            src_side_default, dst_side_default, body_nodes,
        );
        // 排除 src/dst 节点自身的障碍（路径需要进出这些节点）
        let src_node = graph.node(edge.source);
        let dst_node = graph.node(edge.target);
        let filtered_obstacles: Vec<RectF> = obstacles.iter()
            .filter(|o| {
                // 保留与 src/dst 节点 bounds 不相交的障碍
                let overlaps_src = src_node.map_or(false, |n| n.bounds().intersects(**o));
                let overlaps_dst = dst_node.map_or(false, |n| n.bounds().intersects(**o));
                !overlaps_src && !overlaps_dst
            })
            .copied()
            .collect();
        if let Some(waypoints) = route_edge(
            src, dst, src_side, dst_side,
            &filtered_obstacles,
            rust_agent_flow::routing::GRID_CELL_SIZE,
        ) {
            routes.insert(edge.id, waypoints);
        }
    }
    routes
}
```

```rust
/// 绘制路由边：对 waypoints 应用圆角后绘制折线 + 箭头。
///
/// - Bezier: round_corners(waypoints, 24.0) → 更大圆角模拟平滑曲线
/// - SmoothStep: round_corners(waypoints, 12.0) → 与普通 SmoothStep 一致
/// - Step / Straight: 直接使用 waypoints（直角折线）
pub(crate) fn paint_edge_routed(
    waypoints: &[PointF],
    edge_type: EdgeType,
    scale: f32,
    offset: Point<Pixels>,
    color: Rgba,
    window: &mut Window,
) {
    let points = match edge_type {
        EdgeType::Bezier => round_corners(waypoints, 24.0),
        EdgeType::SmoothStep => round_corners(waypoints, 12.0),
        _ => waypoints.to_vec(),
    };
    let is_bezier = false; // 路由边始终用折线绘制（round_corners 已采样曲线）
    paint_polyline(&points, is_bezier, false, scale, offset, color, window);
    paint_arrow(&points, is_bezier, scale, offset, color, window);
}
```

## 设计决策与假设

### 决策 1：网格分辨率 = 10px/cell
- 2000×1500 画布 → 200×150 = 30K 格，A* 搜索空间小
- 10px 精度足以避免视觉碰撞（节点最小 35px 高）
- 过小（5px）→ 网格过大，A* 变慢；过大（20px）→ 路径粗糙

### 决策 2：障碍外扩 margin = 15px
- 确保路径与节点保持视觉间距
- 小于 nodesep（40px），不会过度限制可用空间

### 决策 3：拐弯惩罚 = 2.0
- 每次方向变化增加 2 格代价，鼓励直线段
- 太高（10+）→ 路径宁愿绕远也要少拐弯；太低（0）→ 锯齿路径

### 决策 4：Straight 边跳过路由
- Straight 边语义是「直线直连」，路由后会变成折线，语义冲突
- 用户选择 Straight = 接受可能的视觉重叠

### 决策 5：LoopBack 边跳过路由
- LoopBack 边有专用的 `loop_back_path`（5 点 U 形），语义明确
- A* 无法理解「必须绕过 Loop 下方」的语义约束

### 决策 6：路由失败回退到几何路径
- A* 可能因网格过大、障碍包围等原因失败
- 回退到现有的 `paint_edge_scaled`（Normal 变体），系统永不中断

### 决策 7：所有路由在 relayout 时一次性计算并缓存
- 避免每帧重复 A* 搜索
- 图结构变化（增删节点/边）触发 relayout → 重新路由
- 拖拽/平移不触发 relayout → 复用缓存

### 假设
- 节点尺寸 ≥ 35px（demo 中最小节点高度），10px 网格可正确表达
- 画布尺寸 < 5000×5000（50K 格），A* 在 < 50ms 内完成
- demo 使用场景节点数 < 50，性能无忧
